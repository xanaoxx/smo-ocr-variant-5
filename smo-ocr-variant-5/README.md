## Вариант СМО

`ИБ ИЗ1 ПЗ2 Д1ОЗ1 Д1ОО1 Д2П1 Д2Б5 ОР1 ОД2`

| Код | Правило |
| --- | --- |
| ИБ | Корпоративные подразделения и информационные системы постоянно формируют задания на OCR-распознавание документов; источник имеет неограниченное число возможных заявок |
| ИЗ1 | Поток OCR-заданий задаёт пуассоновский поток поступления заявок от источников |
| ПЗ2 | OCR-сервер (worker) непосредственно распознаёт текст документа; время обработки случайное и подчиняется равномерному закону в заданном диапазоне |
| Д1ОЗ1 | Менеджер кольцевой очереди ставит новую заявку в очередь по кольцу: поиск свободной ячейки начинается с текущего указателя; после записи указатель переходит на следующую позицию |
| Д1ОО1 | Модуль контроля переполнения очереди: если очередь полностью заполнена, удаляет заявку, стоящую под текущим указателем, и помещает на её место новую заявку |
| Д2П1 | Планировщик OCR-серверов выбирает вычислительный сервер по приоритету номера: каждый поиск начинается с самого приоритетного сервера, заявка назначается первому свободному |
| Д2Б5 | Программный планировщик заявок объединяет заявки одного источника в пакет, выбирает наиболее приоритетный пакет и передаёт его заявки на обработку до исчерпания пакета; затем выбирает следующий |
| ОР1 | Сводная таблица результатов: после моделирования показывает количество заявок, отказы, времена ожидания/обслуживания и использование серверов |
| ОД2 | Формализованная схема системы: в пошаговом режиме показывает текущее состояние источников, буфера, диспетчеров и OCR-серверов |

## Допущения, которые нужно подтвердить по методичке

1. Приоритет источников: наивысший приоритет у источника с наименьшим номером (в атрибуте `priority`). В исходных материалах это не определено.
2. Порядок заявок внутри пакета — по времени прихода.
3. Пакет считается завершённым, когда обслужены все его заявки; пока это не так, свободные серверы простаивают.
4. Ёмкость буфера, число серверов и источников, λ и границы a, b — параметры модели, значения не заданы.
