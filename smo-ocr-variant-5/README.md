# СМО — центр OCR-обработки документов (вариант 5)

Моделируется центр OCR-обработки: подразделения и информационные системы (источники) отправляют задания на распознавание сканов и PDF-файлов. Заявки ждут в ограниченном кольцевом буфере и обрабатываются OCR-серверами. Отказ возможен только в буфере (вытеснение), серверы не отказывают, а бывают заняты.

Проект содержит артефакты проектирования (PlantUML). Программной реализации в репозитории нет.

## Вариант СМО

`ИБ ИЗ1 ПЗ2 Д1ОЗ1 Д1ОО1 Д2П1 Д2Б5 ОР1 ОД2`

| Код | Правило |
| --- | --- |
| ИБ | Источники заявок |
| ИЗ1 | Интервалы между поступлениями — экспоненциальные (пуассоновский поток) |
| ПЗ2 | Время OCR-обслуживания равномерно распределено на интервале U(a, b) |
| Д1ОЗ1 | Кольцевой буфер фиксированной ёмкости; поиск свободной ячейки начинается с текущего указателя, после записи указатель сдвигается |
| Д1ОО1 | При полном буфере новая заявка записывается в ячейку под указателем, вытесняя находящуюся там заявку; вытесненная учитывается в статистике, указатель сдвигается |
| Д2П1 | Для заявки выбирается первый свободный сервер по порядку номеров |
| Д2Б5 | Выбирается источник с наивысшим приоритетом; пакет — все его ожидающие в буфере заявки; состав пакета фиксируется при создании, новые заявки не добавляются |
| ОР1 | Сводная таблица статистики |
| ОД2 | Пошаговое отображение состояния системы |

## Правила модели

- **Триггеры.** Диспетчеризация запускается только событиями календаря: поступлением заявки (после постановки в буфер) или освобождением сервера.
- **Буфер.** Кольцо из N ячеек и указатель. Заявка пишется в первую свободную ячейку, начиная с указателя; указатель ставится за записанную ячейку. Если свободных ячеек нет, заменяется заявка в ячейке под указателем (не самая старая и не самая низкоприоритетная), указатель сдвигается.
- **Статистика вытеснения.** Вытесненная заявка получает статус «вытеснена» и учитывается один раз; новая заявка учитывается как принятая. Доля отказов = вытесненные / сгенерированные.
- **Пакет.** Формируется, когда активного пакета нет, есть свободный сервер и буфер не пуст. Состав — все заявки выбранного источника, лежащие в буфере в этот момент. Позже пришедшие заявки остаются в буфере. Все серверы обслуживают только один пакет; новый пакет формируется после полной обработки текущего (последняя заявка завершена).
- **Сервер.** Первый свободный по порядку номеров 1..N (не по указателю). Время обслуживания — U(a, b).
- **Статистика ОР1.** Число сгенерированных, принятых, вытесненных и обслуженных заявок, доля отказов, среднее время ожидания (начало обслуживания − приход), среднее время обслуживания, загрузка каждого сервера (занятое время / время моделирования).
- **Режим ОД2.** После каждого события показывается состояние: источники, ячейки буфера и указатель, активный пакет, серверы, календарь событий, счётчики.

## Допущения, которые нужно подтвердить по методичке

1. Приоритет источников: наивысший приоритет у источника с наименьшим номером (в атрибуте `priority`). В исходных материалах это не определено.
2. Порядок заявок внутри пакета — по времени прихода.
3. Пакет считается завершённым, когда обслужены все его заявки (так сказано в требованиях преподавателя); пока это не так, свободные серверы простаивают.
4. Ёмкость буфера, число серверов и источников, λ и границы a, b — параметры модели, значения не заданы.
